# ai-sales-plan · 化学药剂售前方案平台

面向应用型化学药剂与特种化学品售前，将应用诊断、证据查证、产品路线、样品试验、客户价值、部门审核和批准版 Word 交付放在统一 AI 工作空间。

更新日期：2026-11-07。当前软件版本为 `0.5.0`，数据库迁移要求为 **10**。三批基础业务链已接通；真实化工专业质量、人工收益与生产运行仍待独立验收。

## 使用入口与主要能力

新建或打开**任意方案**，默认进入统一 AI 工作空间。场景由客户问题和资料决定，PCBA 清洗是合成验证样板，不需要寻找专用方案入口。

| 工作区 | 当前能力 |
| --- | --- |
| AI推进 | 提交目标及资料许可；真实 Pi Agent 多步查证；查看工具过程、实际已读/未读范围、诊断、追问与正文候选；人工采用 |
| 应用与路线 | 事实、假设、问题及答复；同属性数值冲突；路线候选/选定/排除、反证、重新考虑条件、案例条件差异与原文引用 |
| 样品与试验 | 计划、样品批次、方法/工况/对照、原始读数及单位、确定性判据、独立技术结论与失败路线阻断 |
| 价值与商务 | 客户应用成本与条件敏感性；内部报价、毛利及项目贡献；独立财务和条件审核分工 |
| 商机、待办与交付 | 商机受理、责任人/期限/完成依据、个人待办、实际交付对象/渠道/批准版本/文件指纹 |

通过“方案编制与送审”进入正文、产品关联、预检、整篇阅读和审核。正式 Word 从批准快照生成，同版重复下载保留原文件；下载与实际交付登记分开管理。

支持工程师、化学师、合规、财务、供应质量、法务、领导和管理员八类角色。新送审执行“技术、合规及适用的供应/法务 → 财务 → 领导终审”；各审核人独立，编制人不能自审。历史三节点批准按原合同读取，不补造财务签字。

## 安装与启动

运行环境：Node.js **>=22.19.0**、MySQL 8。依赖由 `package-lock.json` 固定。

首次部署：

```bash
npm ci --ignore-scripts
cp .env.example .env
```

填写数据库连接及初始管理员配置，`BOOTSTRAP_PASSWORD` 至少12位，再执行：

```bash
npm run db:check
npm run db:migrate
npm run db:bootstrap
npm run build
npm start
```

默认访问 [http://127.0.0.1:3200](http://127.0.0.1:3200)，使用配置的管理员账号登录，随后建立业务账号和审核分工。初始化只创建不存在的管理员，不覆盖已有密码。已有环境保留原 `.env`，升级前备份，执行迁移和构建。

开发运行 `npm run dev`，前端为 [http://127.0.0.1:5173](http://127.0.0.1:5173)。生产需配置实际 `APP_ORIGIN`、`NODE_ENV=production`、HTTPS反向代理及服务托管；MySQL TLS由 `MYSQL_SSL` 单独控制。

## 配置

完整配置见 [.env.example](.env.example)。密码、密钥和私有资料只保存在服务端，不提交版本管理。

| 配置 | 用途与默认值 |
| --- | --- |
| `HOST` / `PORT` | 默认 `127.0.0.1:3200` |
| `APP_ORIGIN` | 浏览器访问来源，与实际地址一致 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_DB` / `MYSQL_USER` / `MYSQL_PASSWORD` | 数据库连接 |
| `MYSQL_SSL` | 数据库TLS开关 |
| `BOOTSTRAP_NAME` / `BOOTSTRAP_EMAIL` / `BOOTSTRAP_PASSWORD` | 初始管理员身份 |
| `MODEL_BASE_URL` | 兼容模型接口地址，默认 `https://api.deepseek.com` |
| `MODEL_ID` | 默认 `deepseek-flash`，以供应商开放型号为准 |
| `MODEL_API_KEY` | 模型密钥；为空时关闭AI生成，保留人工业务流程 |
| `MODEL_MAX_TOKENS` | 单次最大输出token，默认8192，允许512—32768 |
| `JOB_TIMEOUT_SECONDS` | AI任务超时，默认600秒；工作空间总执行上限600秒 |
| `FILE_STORAGE_DIR` | 原件及批准成果目录，默认 `./data/files` |
| `DOCUMENT_FONT` | Word字体，默认 `Microsoft YaHei`，由打开文件的客户端提供 |

模型配置修改后重启服务。阅读许可与模型外发许可分别核验，只有明确选择和许可的业务文本进入配置的模型服务。

## 建议工作顺序

1. 管理员建立业务账号、审核分工、模板和产品；共享TDS、应用说明、SDS等资料由对应专业人员独立复核发布。
2. 工程师新建方案、补充客户私有资料，在AI推进中选择资料范围并提交目标；核对候选及原文后采用。
3. 在应用与路线中确认事实、回答关联问题、处理冲突、比较并选择路线；正式关联产品时固定发布参数版本。
4. 必要时建立试验计划，经独立技术确认后登记原始结果，再形成有限适用范围的专业结论。失败及未知不能靠改写推荐文字消除。
5. 确认客户价值假设、内部商务声明、有效期及条件审核分工；进入方案编制，处理预检后送审。
6. 批准后下载固定Word并登记实际交付和后续义务。修改正式内容时开启新版，旧批准、原文件及交付记录保留。

内部商务底稿仅负责人及本项目指派财务可读，不进入模型上下文或对客Word。纯技术方案也需财务确认费用和承诺范围。

## 当前边界

- 统一Agent已使用 Pi AI / Durable / Chord **1.4.0**，调用配置的真实模型。原单章助手保留直接模型接口，不能把其前12000字符限制套用到统一Agent。
- 主Agent在手选、获准的最多8份资料、合计60万已解析字符内进行全文分段检索和读取；引用须落在实际已读范围。尚无授权全库自动发现、语义召回或PDF物理页码/表格行列锚点。
- 文件支持TXT、Markdown、CSV、DOCX及文本PDF；单文件5MB，提取最多20万字符、PDF前50页。不支持扫描件OCR和XLSX。
- 已有对象依赖、变化事件和人工发起的AI修订准备；尚无事件模型自动执行预授权，也未实现精确到章节的局部补丁采用。
- 案例条件比较由人工整理；金额采用精确JSON字符串快照与BigInt计算，尚无独立DECIMAL统计投影、税额或汇率模块。
- 当前证据以合成样板为主。联合恢复、托管监控、供应商账单核对、Word/WPS实际排版、真实专业质量及生产权限仍待验收。

完整的八方向实施核查与后续退出条件见[解决方案第0章](docs/售前业务全流程解决方案.md#0-当前实施状况与剩余差距)。

## 验证与运维

基础检查：

```bash
npm test
npm run build
node --import tsx scripts/storage-check.ts
node --import tsx scripts/check-runtime.ts --report
```

专业/商务完整HTTP验收使用临时合成数据，请在隔离验证环境串行执行，按实际服务设置地址：

```bash
PROJECT_VERIFY_BASE=http://127.0.0.1:3200 node --import tsx scripts/verify-project.ts
```

需要真实模型或浏览器时，在上面的命令追加 `--ai`、`--browser`；前者消耗模型额度，后者需独立Chrome调试端口9333。报告保存在本机 `data/qa/project/`，不纳入版本管理。最近的工程验证范围与证据时效见[设计文档](docs/设计文档.md#10-验证证据与验收边界)。

`npm run eval:pcba`、`npm run poc:pcba`保留早期合成评测与离线执行底座实验。旧三节点演示和验收脚本属于历史基线，不能替代当前财务及条件审核验收。本机旧演示材料索引为 `data/demo/latest.json`，账号仅留在私有批次目录，不复制进公共文档；不同角色演示需独立浏览器会话。

MySQL保存业务及任务，`FILE_STORAGE_DIR`保存原件和批准文件，`data/workspace/`保存Pi日志及输入清单。备份恢复必须联合覆盖这些内容及配置；SQLite需停写或使用正确备份机制，不能只复制正在写入的主文件。当前恢复面向单机，不承诺外部请求只计费一次。独立巡检脚本尚未托管定时运行，不等于已部署监控告警。

资料撤回、过期或失去授权后，新的采用、送审或下载可被阻断；历史批准快照和原文件仍保留。
